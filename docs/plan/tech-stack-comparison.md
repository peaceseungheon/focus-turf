## 2. 검토 배경 및 범위

PRD §12는 크로스플랫폼 앱(Flutter 또는 React Native)을 전제로 하고, 프레임워크 최종 선택을 개발 착수 전 사용자 결정 사항으로 남겨두었다(§18-3). 본 문서는 이 결정을 지원하기 위해 PRD 요구사항을 평가 기준으로 변환하고, 2026-08 시점의 프레임워크 현황과 생태계 조사 결과를 대입해 비교한다.

지도 SDK 선정(§18-2)은 별도의 오픈 결정사항이며, 프레임워크 선택과 상호 의존적이다. 본 문서는 이 상호 의존성을 시나리오로 명시한다(§7).

**범위 외:** 지도 SDK 자체의 오버레이 성능 실측(Spike, §18-2), 백엔드 스택, 수익 모델.

### 아키텍처 노트: '지오펜싱'의 실체 (가중치 조정 사유)

PRD의 타일 경계 검증은 OS 수준 지오펜싱이 아니라 **포그라운드 위치 샘플링(15초 주기 가설) + H3 셀 판정 연산**으로 충족 가능하다. 세션 중에만 위치를 받아 좌표→H3 인덱스 변환(`latLngToCell`, 순수 연산)으로 "현재 타일"을 판정하고, 이탈 여부는 히스테리시스(60초)로 확정한다. 따라서 생태계 비교에서 '폴리곤 지오펜싱 플러그인'의 가중치는 낮게 반영하며, C3의 본질은 **안정적인 포그라운드 위치 스트림**이다. 백그라운드 위치(선택 권한)는 화면 꺼짐 상태 타이머 무결성 보조 용도로만 필요하다.

## 4. 프레임워크 현황 (2026-08 기준)

### Flutter

- **최신 안정 버전:** 3.47.2 (2026-08-27), Dart 3.13.2. 2026년 3개의 메이저 릴리즈(2월 3.41 / 5월 3.44 / 8월 3.47)로 3~4개월 주기 유지 중.
- **렌더링:** Impeller가 모든 플랫폼 기본(iOS에서는 유일 엔진, Android API 29+ 기본, 데스크톱 기본). 빌드 타임 셰이더 선컴파일로 런타임 jank 제거. 커스텀 드로잉(캔버스·폴리곤·차트류)에서 직접 GPU 파이프라인 사용이 강점.
- **알려진 이슈:** Snapdragon 8 Elite Gen 5(Adreno 830/840)에서 Impeller 성능 저하 이슈가 열려 있음(커뮤니티 워크어라운드: 해당 기기 Skia 강제 전환, flutter/flutter#180958).
- **생태계:** pub.dev 약 29,600 패키지. 핵심 플러그인(location, firebase 등)은 Google 직접 관리.

### React Native

- **최신 안정 버전:** 0.87.1 (2026-08-26). 0.84.x는 지원 종료.
- **아키텍처:** New Architecture(Fabric + TurboModules + JSI + Bridgeless)가 0.76부터 기본, 0.82에서 레거시 브리지 완전 제거. 프로덕션 마이그레이션 사례에서 콜드스타트 최대 43% 개선 등 보고됨(맥락별 편차 큼, 범용 수치 아님).
- **알려진 이슈:** react-native-maps에서 Fabric(Android) 환경 폴리곤/폴리라인 오버레이가 갱신 시 미갱신·고스트 잔존 등 불안정 동작 이슈가 열려 있음(react-native-maps#5932). 본 서비스의 육각 그리드와 직접 관련된 항목이다(단, §5의 네이티브 맵 SDK 경로에는 해당하지 않는 이슈다).
- **Expo:** SDK 51+ New Architecture 완전 지원. 관리형 워크플로우로 초기 구성 부담 축소.
- **생태계:** npm(1M+ 패키지) 기반으로 절대 규모는 크나, RN 전용 네이티브 모듈의 유지보수 상태는 개별 패키지별 확인이 필요.

### 시장 지표 (참고)

- GitHub 스타(2026-08): Flutter 약 178.6K vs RN 약 126.4K.
- 채용 풀: RN은 JS/TS 인력풀(가장 큰 풀)에서 충원 가능, Flutter는 Dart 숙련자 필요(상대적으로 작은 풀).
- 국내: 카카오·배민(일부) 등이 Flutter 채택 사례. 시각·애니메이션 중심 소비자 앱에서 Flutter 채택 강세라는 분석이 있음. RN은 JS 기반 팀·에이전시 중심 채용. 정량 데이터는 부족하며 참고 수준.

> ⚠️ 벤치마크 수치(FPS, 콜드스타트 등)는 출처가 서드파티 블로그로 권위가 제한적이다. 본 문서는 방향성 판단에만 사용하고, 최종 성능은 Spike(PoC)에서 실측한다.

## 5. 생태계 비교 (요구사항별)

기호: ◎ 강함 / ○ 보통 / △ 약함. 패키지 정보는 2026-08-31 리서치 시점이며 버전은 변동 가능하다.

### 5-1. 국내 지도 SDK (C1)

| 항목 | Flutter | React Native | 우위 |
| --- | --- | --- | --- |
| 카카오맵 | `kakao_map_sdk` v1.4.x 계열 — 활동적, 폴리곤(Polygon·ShapeController) 문서화. `kakao_maps_flutter`(SDK v2) 등 후보 다수 | `@react-native-kakao/map` v2.x — 활동적이나 주간 다운로드 수십 수준, 폴리곤 지원 미확인. 웹용 라이브러리만 성숙 | **Flutter** |
| 네이버 지도 | `flutter_naver_map` — 활동적, 폴리곤 지원. NCP 지도 서비스 체계 전환(무료티어 정책 변동)에 따른 마이그레이션 이슈 존재 | `@mj-studio/react-native-naver-map` v2.9.0(2026-05) — 매우 활동적, TypeScript, 주간 2.1K 다운로드, 폴리곤 지원 | **RN** |
| Mapbox | `mapbox_maps_flutter` — **Mapbox 공식** 패키지, 벡터 타일·GeoJSON·필 레이어 | `@rnmapbox/maps` v10.x — 커뮤니티, 주간 220K 다운로드, 매우 성숙 | 근소 RN(채택량) / 공식성은 Flutter |
| OSM 자체 렌더링 | `flutter_map` + Impeller 커스텀 렌더링 조합이 현실적 대안 | 자체 렌더링 파이프라인 구축 비용 큼 | **Flutter** |

**해석:** 프레임워크 우위가 지도 SDK 선택에 따라 뒤집힌다. 카카오맵을 쓰면 Flutter, 네이버 지도를 쓰면 RN이 유리. 지도 SDK가 미확정인 현재, **최악의 경우를 비교하면 Flutter(네이버 래퍼 ○)가 RN(카카오 래퍼 △)보다 안정적**이다.

### 5-2. 위치 검증·타이머·배터리 (C3, C4, C5)

| 항목 | Flutter | React Native | 우위 |
| --- | --- | --- | --- |
| 포그라운드 위치 스트림 | `geolocator`(사실상 표준, 활동적) 등 | `expo-location` / 커뮤니티 모듈 | 무승부 |
| 배터리 인식형 트래킹 | `tracelet`(배터리 예산 엔진, 활동 분류), `allinone_location`(칼만 필터·데드레코닝) 등 정교한 패키지 다수 | 유료 TransistorSoft 제품이 사실상 유일한 고급 옵션 | **Flutter** |
| 백그라운드 타이머 무결성 | 단일 이벤트 루프 + 플랫폼 채널. 네이티브 보완 필요 | JS 타이머는 화면 꺼짐 시 정지. `react-native-nitro-bg-timer-plus`(포그라운드 서비스 기반) 등 네이티브 보완 필요 | 무승부 (양쪽 모두 네이티브 모듈 병행이 정석) |
| OS 제약 | Android OEM 배터리 최적화, iOS 백그라운드 제한 — 프레임워크 무관 | 동일 | 무승부 |

**해석:** 양 프레임워크 모두 "순수 프레임워크 API만으로 해결"은 불가능하고 네이티브 모듈 병행이 전제된다(PRD §12도 동일 전제). 차이는 배터리·위치 고급 패키지의 오픈소스 선택 폭에서 Flutter가 우위.

## 8. 권장안 (조건부)

### 기본 권장: Flutter

근거:
1. **경로 강건성** — 지도 SDK가 아직 미확정(§18-2 Spike 대기)인 상황에서, 어느 국내 SDK가 선정돼도 Flutter에는 사용 가능한 래퍼가 존재한다(카카오 ◎·네이버 ○·Mapbox 공식·자체 렌더링 탈출로). RN은 카카오맵 조합에서만 유의미한 약세를 갖는다.
2. **육각 그리드 렌더링 여지** — 맵 SDK 오버레이 성능이 Spike에서 불충분할 경우, Impeller 기반 자체 렌더링(E 시나리오)으로 우회할 수 있는 프레임워크는 Flutter뿐이다.
3. **배터리·위치 패키지 깊이** — 세션 중 15초 샘플링·배터리 예산 같은 요구(C3·C5)에 대응하는 오픈소스 선택지가 더 많다.
4. **국내 시장** — 시각 중심 소비자 앱에서의 채용 강세(카카오 등). 단, 정량 근거는 약하다(§4 참고).

### React Native를 권장하는 조건

다음이 모두 성립하면 권장안이 뒤집힌다:
1. 개발 주체(팀/사용자)가 **React/TypeScript 역량 보유**로 즉시 생산성 확보가 가능하고
2. 지도 SDK가 **네이버 지도**로 수렴하거나 Mapbox로 확정되며
3. 자체 렌더링 탈출로(E)가 요구사항에서 배제되는 경우

### 결정 필요 입력값

- 개발 주체의 기존 스킬(React/TS · Dart/Flutter · 네이티브 · 학습 시작)
- 지도 SDK 선호(카카오 · 네이버 · Spike 결과에 따름)
